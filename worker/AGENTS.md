- Cloud rendering: `render_jobs` queue (lease claim via `claim_render_job`, heartbeat, `fail_render_job` refunds once) processed by the FFmpeg worker in `worker/` (Railway); browser export stays the live path until the worker is proven. Why: renders must survive a closed browser.
- The worker authenticates to the `worker-api` edge function with `WORKER_SECRET` only; it never holds the service-role key or Google refresh tokens, and every action is bound to the job it holds the lease on. Why: a compromised worker can't reach other users' data or credits.
- Hands-off Autopilot: worker polls `autopilot_runs` (claim_autopilot_run), runs script then missing scene assets via normal generate-script/scene-asset with a 10-min HMAC task token, then queues one render job (`autopilot:<plan>`); plans capped at 20 minutes (client + worker-api). Worker render mirrors browser export (synth.mjs, motion.mjs, typewriter.mjs are copies of src/lib music/sfx/motion/typewriter — keep in sync). Cloud plans need `autopilot_cloud_eligible` (admin, or Creator/Pro when the `app_flags.autopilot_customers` switch is on, enforced by trigger + claim); YouTube upload only when `publish_consent`. Why: same credits, retries never pay twice, no posting without permission.
- Live website recording (product-ad website scenes): `web-record` charges the animate cost and queues `web_recordings`; the worker records the page with Playwright Chromium (`webrec.mjs`: visible cursor, one same-site click, smooth scroll; navigation locked to the ad's domain) and uploads via a signed URL; `worker-api` web_done sets `clip_path`, web_fail refunds after 3 attempts; stale queued jobs refund on status read. Why: real interaction can't be faked by AI video, and no credits are lost if the worker is down.
